# Endpoint & Dependency Inventory

Sprint 1 deliverable: what this test suite actually talks to, and what it
depends on to run. Scope is CLM QA only (see Sprint 1 baseline report for
why).

## External endpoints called

| Endpoint | Method | Purpose | Called from |
|---|---|---|---|
| `https://login.microsoftonline.com/{TENANTID}/oauth2/v2.0/token` | POST | Microsoft Entra ID (Azure AD) OAuth2 token, Resource Owner Password Credentials (ROPC) grant, for the CreationAdmin test user | `auth/login.ts` |
| `{REDIRECTURI}/api/specification/templatesearch/search` | POST | General/filter search - the same call the CLM UI makes from Search Templates → Filter Search | `pages/Search/search.ts` |

For CLM QA, `REDIRECTURI` resolves to
`https://clm-qa.southafricanorth.cloudapp.azure.com/`.

## Dependencies

**Runtime**
- k6 with native TypeScript support (v0.57+; validated against v2.0.0). No bundler, Babel, or Webpack step - k6 transpiles `.ts` directly.
- Node.js + npm - only needed for `npm run build` (a `tsc` type-check) and `generate-config.js`, not for actually running the tests.

**Identity / access**
- Azure AD tenant: `TENANTID` (CLM QA tenant)
- App registration: `HUBCLIENTID` / `CLIENTSECRET` (scoped as `api://{HUBCLIENTID}/user.read`)
- Test user: CreationAdmin (`Creationadmin@korbicomgdtest.onmicrosoft.com`), password stored in `k6.env.qa.json`
- Org context: `ORGID`, sent as the `x-ghostdraft-organization` header on search calls

**Local config**
- `k6.env.qa.json` (gitignored, must exist locally, never committed) - the single source of environment + credential data for the CLM QA target
- `config.json` (generated by `generate-config.js`, gitignored) - a secondary flattened summary, currently **not consumed** by the test itself (see Technical Debt Inventory, item 7)

**npm packages**
- `typescript`, `@types/k6` - dev-only, for type-checking/IDE support. Neither is required to actually `k6 run` a test.
